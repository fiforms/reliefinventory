# Stock by pallet / location

`item_ledgers` stays pooled. Where goods physically are comes from two append-only sources summed by `App\Services\PalletStock` (no stored running totals, so nothing drifts): `pallet_stock_assignments` (signed qty put on a Warehouse `W` pallet) and ledger rows with `stock_pallet_id` (a fill picked from a pallet; sorting straight onto a pallet is supported but unbuilt). "Unassigned" = what's still in the sorting area (plus pre-feature stock) = on-hand minus everything on pallets. A pallet can't take more than `PalletStock::unassigned()`; it empties automatically at 0. Items not put on a pallet can't be located.

## Fill Pallet (Inventory Movement > Pallets tab)
One scan-driven screen (`PalletStockController::fill`). An always-focused scan bar takes a pallet (location, status, contents, history; move, change status, add items if W) or, with a pallet showing, a location barcode (records the move at once). With no pallet showing it builds a new W pallet from `/json/pallet-stock/staging` (the pick-up list), sealing it and setting its location in one step. Locations and Recent Movements are separate tabs.
- Sealed W pallet: can only be moved or unsealed. Open: can be re-sealed, take items from the sorting area, or (if it has a location and the user holds `adjust-inventory`, separate from `manage-pallets`, default Office/Administrator) have contents adjusted by hand with a required reason (shrinkage, damaged, correcting count/item type, other); mutually exclusive in the UI.
- An adjustment is its own `orderdonations` row (`type='adjustment'`, `adjustment_reason`) whose ledger rows carry `stock_pallet_id`, so it changes stock itself.

## Picking from pallets
A *sealed* pallet is never picked until opened (`POST /json/order-filling/pallets/{id}/open`); only `open` pallets are. A fill naming no pallet takes the unassigned pool first, then the oldest open pallets (split across them; one ledger row per source; the POST returns `records`). If still short and sealed pallets hold the item: refused (422, nothing written, `sealed_pallets` lists what to open). If no pallet holds it: accepted as a true over-pick with a warning (the only way unassigned goes negative). `GET /json/order-filling/stock/{itemtypeId}` feeds the "Where it is" display. Planning: see `orders-and-filling.md`.

## Inventory labels (`InventoryLabelController`, document `inventory-labels`)
One label per `pallet_stock_assignments` row with qty > 0, coded `ACS:<family>-<variant>:<row id>` (`App\Support\InventoryLabelCode`; `parse()` returns the row id for a future scan). Shows item number, item type, qty, earliest expiration (the assignment's own `expires_on`; older rows null) and pallet. Media: `LabelSetting::inventoryMedia()` (default `label_small`, set on `/setup/printers`; shared prop `printing.inventoryLabelMedia`). The ~230-module Code 128 doesn't fit 2.312 in across, so the compact layout rotates it down the 4 in length. `App\Support\LabelBarcode` draws every bar in whole 203-dpi dots with a quarter-dot inset (Ghostscript without anti-aliasing otherwise grows bars by a dot); `InventoryLabelTest` rasterizes a label and fails if any bar/gap isn't a whole number of modules. Labels show quantities as added; later picks/corrections aren't reflected. After Fill Pallet the result offers Print Item Labels; a scanned W pallet lists its labels for reprinting.

Not built: scan-an-inventory-label-to-find-stock; sorter→pallet tracking at sort time.
