# Barcode scan → item

`UpcController`, `App\Services\Upc\{UpcResolver,UpcLookupService}`, `App\Helpers\Gtin`; UI in `DonationSorting.vue` via `SearchSelect`'s `scanDigits`/`scan`. Enter on an all-digit 8/12/13/14-character entry calls `GET /json/upc/resolve`.

- **No separate table for single-item UPCs.** A manufacturer UPC lives on a SKU row of the master item list (`items.upc`; many SKU rows, each with its own UPC, under one ACS item type). Every code is normalized to 14 digits by `Gtin::normalize`, so UPC-A/EAN-13/GTIN-14 are one key. Items hold one UPC each, so two barcodes for one product are two rows.
- **Cartons** (14-digit GTIN, indicator 1–8) are mapped, not added as products: `carton_codes` (`code` → single-unit `item_id` + `qty_per_carton`, entered as packs × items per pack) is checked first and selects the *contained* item with qty filled in, so carton and single scans land on one row and "Combine duplicate lines" merges them. Older case SKU rows (own `items.upc`, `case_qty` > 1) still work (`qty = case_qty × size`).
- **Miss path:** check digit (bad = misscan, 422) → classify (carton vs single; a retail multipack with an ordinary UPC is told apart only by the person) → guess a carton's single-unit code (`Gtin::guessEachCode`, GS1's one-item-case convention; often right, often not, so `candidates` lists items with the same manufacturer prefix) → unless a single-unit row is found, ask Open Food Facts then Open Products Facts for a *suggestion* (`config/upc.php`; sends only the barcode; ~10 requests/min install-wide under their 15/min/IP ban line; found cached 30 days, "none" 3 days, outages never cached; off in Offline Mode or `RI_UPC_LOOKUP=false`; never throws). The online lookup is a separate, slower request (`/json/upc/suggest`) so the form doesn't wait on the network.
- Sorting then opens **Add New Item** (`Components/NewItemModal.vue`) prefilled; an unknown carton opens **New Carton Barcode** (scan one of the singles inside, pick it, or choose a candidate; then packs × items per pack; `POST /json/upc/cartons`).
- **Nothing is stored until the sorter saves** (`POST /json/items` / `POST /json/upc/cartons`). Lookups/confirmations are `manage-sorting`; carton codes list/remove via `GET/DELETE /json/carton-codes` (`manage-items`, no admin page yet).

## Sources not wired in, and a bulk-dump option
- **Other free sources** (add under `config/upc.php` `sources` + a case in `UpcLookupService::parse()`): UPCitemdb (broad general merchandise; free Explorer plan 100 lookups+searches/day, no key, `/prod/trial`; read its terms before storing anything from it); BarcodeFinder (advertises 1,000/day free, unverified against its own docs). Paid or tiny-free and not worth it now: Go-UPC, Barcode Lookup, Barcode Report.
- **Bulk dump, if online-per-scan ever isn't enough** (e.g. a site with no Internet): Open Food Facts and Open Products Facts publish full exports (JSONL, CSV, Parquet, Mongo dump; ODbL, attribution required). Import a filtered copy (by country/category; the food dataset is large) into a local table and query it ahead of the online chain. Not built.
