# Reports

All gated on `view-reports`. Built the same way: a controller with `index` / `pdf` / `pdfBuilder` / `csv`, a public `FILTER_RULES`, `buildReport()`, a Blade PDF view, a `DocumentRegistry` entry, and a Vue page with `PrintMenu`. Charts use Chart.js via `Components/ChartCanvas.vue` (bar/line only; every chart has its numbers in a table beside it; no dual-axis); PDFs are tables only.

- **Inventory** (`InventoryReportController`) and `WarehouseMetrics` both aggregate `item_ledgers` (usable additions − subtractions). The item-type detail shows quantity by pallet location plus the unassigned remainder. "Received New" sums `item_condition = 'new'` (all-time received, not new-on-shelf).
- **Outstanding Orders** (`/reports/orders`) and **Unfulfilled Requests** (`/reports/unfulfilled`, requested vs. filled per item by the partner's county and zip, finished requests only; `UnfulfilledRequestsReportController::FILLED_STATUSES`).
- **Sorting area** (`/reports/sorting-area`, `SortingAreaReportController`; on-screen + CSV, no PDF yet): per item sorted vs. put on pallets in a range, plus what's still in the sorting area and since when. Relies on sorting additions never carrying `stock_pallet_id`.
- **Flow** (`FlowReportController`, `/reports/flow`): from `item_ledgers` joined to transaction `type`: donation → received (usable) / lost (outdated, trashed, diverted); order → picked; else adjustments by `adjustment_reason`. Stock effect = (usable ? added : 0) − subtracted, so opening + received − picked + adjustments = stock-on-hand (tested against Inventory). Buckets day/week (Monday)/month, default last 90 days by week, refused above `MAX_BUCKETS`. Pallet moves aren't stock changes.
- **Partner** (`PartnerReportController`, `/reports/partners`): per partner (names shown, unlike Unfulfilled): requests, units requested/filled, shipped/delivered, last request, county roll-up, per-request drill-down. Fill rate counts finished requests only.
- **Donor** (`DonorReportController`, `/reports/donors`): per donor, sorted units by disposition, loss % ((outdated + trashed) ÷ all sorted; diverted doesn't count against a donor), loss % of the last three donations, per-donation loss.
  - **Standing** (`people.donor_standing` preferred/normal/watch/decline + note/set_by/set_at; history `donor_standing_log`) is a human decision: `PUT /json/people/{id}/donor-standing`, `manage-donor-standing` (Office/Administrator), decline needs a note, the Unknown Donor can't have one, not mass-assignable. `DonorStanding::suggest()` only suggests, from `config('inventory.donor_standing')` (starting values, meant to be tuned). Receiving warns under the donor for watch/decline; it never blocks.
  - Not built: the donor notification letter; a standing badge on Donation Offers / People.
- **Training** (`/reports/training`): see `training-warehouse.md`.
